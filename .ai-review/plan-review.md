## 1. 需求與邊界缺漏

| 嚴重度 | 問題 | 為什麼現在不修之後會更貴 | 建議修法 |
|---|---|---|---|
| **High** | **GRADE 各因素的合法分數與適用條件未定義。**目前只寫五項降級可填 `0/−1/−2`、三項升級，未逐項規定合法幅度。傳統 GRADE 中 large effect 可 `+1/+2`，dose-response 與 residual confounding 通常最多 `+1`；publication bias 是否容許 `−2` 也不能由目前規格判斷。 | UI、資料格式、計算、參考答案與測試都會依這些值建立；晚改會同時波及四層。 | 對八個因素逐項列出合法值、適用前提、官方來源定位及非法值行為。不能只規定「總和」。 |
| **High** | **[需查證] A5 的「觀察性 `+2 −1 → Moderate`」可能不是合法 GRADE oracle。**GRADE Handbook 傳統規則通常要求升級適用於方法良好、未先因重大限制降級的觀察性證據；不能在未鎖定原文前直接假定可自由相加。 | 若 oracle 本身錯誤，測試會把錯誤教學永久固定成「正確」。 | 在指定的 `GRADE Handbook 2013` 章節確認「同一證據體能否同時降級與升級」及運算順序；確認前將此期望標為待決，不得作驗收 oracle。 |
| **High** | **GRADE 評估單位不完整。**只寫「單一 outcome」，未定義證據體是純 RCT、純 observational，或混合設計；起始等級由誰、依何規則決定亦未說明。 | 起始等級會進入匯出 schema、UI 與所有參考答案，後補會改資料模型。 | 定義 v1 只接受哪類證據體、研究設計欄位的合法值，以及混合設計明確拒絕或如何處理。 |
| **High** | **CASP 的「整體判斷」沒有方法學定義。**模組表為 `casp.js` 指定「整體判斷」，但 CASP 本質上是逐題 checklist；規格未說整體判斷是學員自由結論、官方規則或程式推導。 | 若先做成演算法，可能創造不存在的官方評分規則，直接構成「教錯」。 | 明定 CASP 不自動產生整體等級；若保留整體欄位，標示為學員綜合結論，不能宣稱 CASP 官方演算法。 |
| **High** | **RoB 2 oracle 未鎖定到精確官方構件。**`rob2@2019-08` 尚不足以識別 guidance 檔名、發布日期、頁／表、effect-of-interest 與 domain variant。`NA` 也未定義是正式答案、條件跳題狀態或未作答。 | 決策表與獨立 oracle 可能從同一份錯誤轉述抄出，全部測試仍會通過。 | 每個 domain 列出官方文件版本、algorithm 表定位、適用 variant；分開定義「未作答」「因路徑未觸及」「官方 NI」，不要統稱 NA。 |
| **High** | **評讀實例生命週期未定義。**D7 使用 `toolId:appraisalId`，但沒有定義 `appraisalId` 的產生、重開、複製、匯入後身份、同檔名 PDF，以及切換 paper 時是否延續舊答案。 | 會造成覆寫、錯誤恢復或把不同文獻答案混在一起；一旦匯出檔流通後很難改 key 語意。 | 增列 appraisal 的建立、續作、另存、匯入與刪除狀態轉移，以及 identity 與 `paperRef` 的關係。 |
| **High** | **版本相符只比較 `toolVersion`，未保證同版本內容不可變。**同一版本下若題目、決策表、mock paper 或參考答案更新，舊檔會靜默與新答案比較。 | 這正是威脅模型第二高風險；發布後才發現時，既有 JSON 已無法可靠判定內容基準。 | 規格明定發布後同一 `toolVersion` 的題目、演算法、mock 與 reference 均不可變；任何影響比對或判讀的變更必須升版。另定義舊版匯入的拒絕或唯讀顯示政策。 |
| **High** | **匯出 schema 只列頂層欄位，沒有欄位型別、必填性、枚舉、未知欄位及巢狀結構規則。** | 各工具可能形成互不相容的 `answers`／`judgements`；schema 驗證會流於只檢查欄位存在。 | 為每個頂層及巢狀欄位定義型別、nullable、合法 enum、未知 key 政策與跨欄位不變量。 |
| **Medium** | **「作答完成」未定義。**D2 的解鎖條件不清楚：所有題目回答、所有必答 SQ、是否需要 judgement、notes／推翻理由是否必填，以及解鎖後修改答案如何處理。 | UI、狀態機及人工驗收會各自採不同定義，後補需改多處流程。 | 為四套工具各自定義 completion predicate，以及解鎖後改答案、清空答案與重新開始的行為。 |
| **Medium** | **localStorage 只定義寫入失敗，未定義讀取到損壞、舊 schema、部分資料或超額資料時的行為。** | 實際故障多發生在載入既有狀態；若沒有失敗契約，容易白畫面或靜默丟資料。 | 增列讀取失敗、資料損壞與不相容狀態的可觀察結果：不載入、不覆寫原值、明示原因，仍可新作答與匯出目前記憶體狀態。 |
| **Medium** | **user PDF 的失敗路徑不完整。**缺損、加密、零頁、超大檔、非 PDF 偽裝檔、PDF.js/CDN 不可用皆未定義。 | PDF 流程完成後再補錯誤狀態，會牽動作答起點與報告內容。 | 在不新增分析能力下，定義可接受檔案、載入失敗時是否仍能空白作答，以及「PDF 不送出瀏覽器」的可驗證邊界。 |
| **Medium** | **匯入內容可能含非預期文字，但報告、比對與錯誤畫面的呈現安全性未列為需求。** | 若 notes、檔名或 JSON 文字被當成標記解析，可能破壞頁面及後續比對。 | `[新增需求]` 所有匯入文字只按純文字顯示。否則可觀察後果是匯入特製檔後畫面結構被改寫或功能失效。 |
| **Low** | **`paperRef = user-pdf:&lt;檔名&gt;` 同時承擔識別與顯示用途。**同名檔案會碰撞，檔名也會進入交付檔。 | 後續若要把 identity 與名稱拆開，需遷移既有 JSON。 | 將規格語意拆成穩定 paper identity 與原始顯示名稱；至少明定同名不代表同一篇。 |

### 方法學優先結論

- RoB 2 overall 規則目前的方向正確：任一 High 為 High、全 Low 為 Low、多個 Some concerns 是否升 High 保留人工判斷。
- 「Y/PY、N/PN 在 algorithm 中等價」應改成「僅在指定官方 algorithm 分支明確合併時等價」，避免成為跨 domain 的無條件規則。
- `[需查證]` CASP 的正式工具名稱、2024 版本標記，以及是否確實存在兩份獨立的「SR-RCT」與「SR-OBS」官方 checklist。規格目前的 `casp-sr-rct@2024`／`casp-sr-obs@2024` 看起來是專案版本名，不足以證明官方版本。
- `[需查證]` CASP 官方題目全文的再發布權限。朋友 repo 無 LICENSE 並不是唯一授權風險；公開逐題重製 CASP 文件本身也需確認使用條款。

## 2. 架構風險

| 嚴重度 | 問題 | 為什麼現在不修之後會更貴 | 建議修法 |
|---|---|---|---|
| **High** | **最難回頭的是已公開 JSON 與教學內容的版本身份，不是前端技術選型。**目前 `schemaVersion + toolVersion` 未明確涵蓋 algorithm/reference/mock 內容。 | 一旦學員檔案流通，無法判定它應與哪版答案比較。 | 將版本不可變性、升版條件與不相容處理列為核心架構契約。 |
| **High** | **D5 的決策表與 A1 的獨立 oracle 仍有 common-mode error。**兩者若由同一人從同一錯誤摘要謄寫，彼此完全一致仍會教錯。 | 完工後才由指導者發現，決策表、測試、參考答案與教材均需重審。 | 要求 oracle 與決策表各自附官方表格 locator，並加一個人工雙人／兩次獨立核對的發布門檻；自動測試不能取代來源核對。 |
| **Medium** | **D3「新增工具只加資料」敘述過度承諾。**只有同一既有引擎語意的新工具才是純資料；新增第四種方法學仍需新引擎與流程。 | 之後可能為維持承諾而把不同方法硬塞進既有抽象。 | 將決策改寫為「同一引擎類型的新工具主要加資料」，不宣稱所有新工具都不需邏輯。 |
| **Medium** | **固定 CDN PDF.js 是單點外部依賴。**雖不違反 GitHub Pages 或無建置限制，但 CDN/CSP/網路失敗會讓 PDF 主流程不可用。 | 等 UI 綁死 PDF viewer 後，降級流程難補。 | 規格定義 PDF.js 無法載入時的明確降級：仍可選工具、作答、匯入及匯出，PDF 檢視不可用並顯示原因。 |
| **Medium** | **「PDF 不離開瀏覽器」是架構承諾，但沒有驗收。** | 若未來加入關鍵字服務或遙測，很容易無意破壞此承諾。 | `[新增需求]` 將「讀取 user PDF 不產生檔案內容的網路請求」納入驗收。否則具體後果是違反已聲明的資料邊界。 |
| **Medium** | **內容授權尚未成為發布阻擋條件。**第 11 節只寫朋友 repo 授權待處理，未處理 CASP 官方題目與可能沿用的互動／版面素材。 | 發布前才處理可能要重寫文字與版面。 | 把兩種授權分開：朋友 repo 不複製的證據、CASP 官方內容的再發布依據；任一未清不得公開發布。 |
| **Low** | **`node:test` 不與「無建置工具」衝突。**測試工具不是部署建置，這部分沒有架構問題。 | — | 保留，但在規格中說明測試只在開發期執行，部署產物仍是原生模組。 |

## 3. 驗證策略缺口：A1–D5

以下每一條都能構造「驗收通過但功能仍壞」的弱化版本，因此目前全部仍有缺口。

| 條件 | 嚴重度 / 弱化實作 | 為什麼之後更貴 | 堵死弱化版本的可證偽斷言 |
|---|---|---|---|
| **A1** | **High**：決策表與 oracle 都從同一錯誤轉錄；或只列無效 Cartesian 組合，漏掉實際條件路徑。 | 錯誤會被測試背書。 | 每個官方 algorithm terminal row 至少對應一個可達案例；每例附官方文件、頁／表／列定位；oracle 與產品決策表不得共享資料來源。 |
| **A2** | **Medium**：放入 5 筆案例，但全部集中於同一 domain，或「官方依據」只寫文件名稱。 | 仍無法抓其他高風險 domain 的誤判。 | 五例須涵蓋預先指定的不同反直覺類別與至少三個 domain；每例具體指出觸發分支與官方 locator。 |
| **A3** | **High**：「任一列應 fail」卻只抽 3 列；可挑最容易被測到的 3 列，其餘死列完全未覆蓋。 | 上線後才發現某列從未被測試。 | 對每個會改變 terminal judgement 或路徑提示的有效決策列，改變其結果後至少一項測試必須失敗；若只抽三列，文字不得宣稱「任一列」。 |
| **A4** | **High**：硬編「正好 3 個 Some concerns」即可通過，但全 Low、1/2 個 Some concerns、任一 High 皆可算錯。 | overall 引擎仍未被驗證。 | 覆蓋全 Low、每一個 domain 單獨 High、1 個及多個 Some concerns、High 與 Some concerns 並存；逐一斷言 judgement 與提示是否出現。 |
| **A5** | **High**：針對三個指定輸入硬編輸出，其餘組合、各因素上限與 clamping 全錯仍通過。 | 錯誤 GRADE 算術會成為核心教學錯誤。 | 先確認合法方法學規則；再逐因素驗證合法幅度、非法幅度、上下界、RCT 禁止升級，以及至少一組非邊界運算。`+2−1` 案例確認官方合法前不得作 oracle。 |
| **A6** | **High**：只在第一個 domain／最後一題未答時回傳無法建議；其他缺題或舊 judgement 殘留仍錯。 | 狀態重入後產生看似權威的過期結論。 | 每個 domain 的每個必答位置各缺一項時均不得有 judgement；條件未觸及題與真正未作答必須可區分；補齊後才產生建議，清除答案後舊建議必須消失。 |
| **B1** | **High**：只測一套工具與簡單答案；匯出及匯入以相同錯誤方式遺漏 notes，仍可能對彼此 deep-equal。 | schema 上線後才能發現跨工具資料遺失。 | 四套工具各用獨立已知 fixture；涵蓋未作答、Unicode、notes、judgements、推翻理由與條件跳題。匯入結果須等於外部定義的 canonical state，而非只與匯出器自身產物比較。 |
| **B2** | **High**：只拒絕列出的六種頂層錯誤，但接受錯誤型別、非法 enum、null、未知題號、缺巢狀欄位。 | 不完整 schema 一旦形成相容性承諾就難收緊。 | 為 schema 每個必填欄位提供缺失、錯型與非法值反例；明定較舊 schema、未知額外欄位及未知 answer key 的接受／拒絕政策。 |
| **B3** | **Medium**：不顯示參考答案及分數，但只顯示部分作答，或仍把 user PDF 誤配到同名 mock。 | 指導者會看到不完整或錯誤內容。 | 匯入後所有 canonical 作答、judgement、notes 均保持；reference 區及 score 不存在；任何 `user-pdf:` 都不得解析為 mock id。 |
| **C1** | **Medium**：所有答案都引用同一個確實存在但無關的段落，因此測試通過。 | 參考理由會指向錯誤證據。 | 每題定義允許引用的段落集合；reference 引用必須屬於該題允許集合，且不得只驗證全域存在。語意正確性仍需指導者簽核。 |
| **C2** | **High**：每題都有 reference 物件，但答案、理由或來源是空字串／占位文字。 | 形式完整掩蓋教學內容缺失。 | 每題 reference 必須有合法判斷、非空理由及至少一個可解析來源；來源類型須區分 mock 段落與方法學文件。 |
| **C3** | **High**：不一致時填入任意空白或「N/A」即可通過。 | 錯誤參考判斷能以形式上的理由逃過驗證。 | 推翻理由須為 trim 後非空且附方法學來源；所有不一致項必須列入指導者人工審定清單。自動測試不宣稱能驗證理由正確性。 |
| **D1** | **Medium**：四套工具各跑一條最短 happy path，即使未作答、改答案、重入或版本不符都壞仍可通過。 | 整合問題會留到課堂。 | 為每套工具指定共同場景矩陣：完整作答、至少一題未答、修改答案、重新載入、匯出匯入、mock 比對；逐步列出預期結果。 |
| **D2** | **Medium**：按鈕被隱藏，但參考內容已在畫面、鍵盤可聚焦，或 URL/狀態切換可展開。D8 已接受原始碼可見，故不能拿「source 可讀」判失敗。 | 完成條件與 UI 狀態補救需改整段流程。 | 在未達 completion predicate 時，正常 UI、鍵盤與重新整理後均無法顯示／展開 reference；達成後才可展開。明確排除檢視原始碼。 |
| **D3** | **Medium**：只測瀏覽器啟動時禁用 storage；但寫滿、寫入中失敗、讀取損壞或 remove 失敗仍白畫面。 | 儲存抽象完成後才補各操作失敗較昂貴。 | 分別驗收讀、寫、更新失敗；每種情況均可繼續作答與匯出、出現橫幅，且失敗不得清除目前記憶體答案。 |
| **D4** | **Medium**：首頁 360 px 無捲動，但題目、比對、報告、錯誤 dialog 或 PDF 畫面溢出；「主題正確」亦無可判定性。 | 全頁完成後才修版面會波及所有元件。 | 指定四套工具各主要狀態在 360 CSS px 驗收；不得有頁面級水平捲動，所有操作可達。深／淺色需驗收文字、控制項、焦點與差異標示均可辨識。 |
| **D5** | **High**：只要 PDF 能打開並點完一次就可宣稱「可上課」，即使 RoB 2 結論錯誤。 | 最後一道門仍抓不到最高威脅。 | 將 D5 定義為發布簽核：指導者先獨立完成預期 SQ、domain、overall 與來源，再與工具輸出逐項核對；所有差異須被判定為合法人工推翻或阻擋發布。 |

另有一個橫向缺口：第 9 節的「雙語、官方原文與教學補充分離、每題來源」除 C2 的弱檢查外沒有完整驗收，因此即使 A1–D5 全過，也可能違反內容規範。

## 4. 更簡單的替代方案

| 嚴重度 | 問題 | 為什麼之後更貴 | 建議修法 |
|---|---|---|---|
| **Medium** | **A1 要求所有 SQ 的 Cartesian 組合可能 over-engineering，且大量組合在條件路由下不可達。** | 測試數量巨大但不能增加方法學信心，維護成本高。 | 改以「每個官方決策列／可達終點、每個等價類及每個條件跳轉都覆蓋」為完整性標準；保留少量跨題組合測試。 |
| **Medium** | **CASP 整體判斷引擎可能是不必要抽象。**若官方 checklist 沒有 overall algorithm，新增它反而有教錯風險。 | 之後需移除衍生分數及既有匯出欄位。 | CASP v1 僅保存逐題答案與學員自由摘要；待有明確、具來源的整體規則才新增。 |
| **Medium** | **PDF 關鍵字比對沒有對應目標或驗收，卻增加 PDF 處理與誤導風險。** | 容易演變成半自動判讀功能，消耗測試與教學說明成本。 | v1 可只提供 PDF 檢視與人工作答；若保留關鍵字比對，至少把它列成明確需求及可接受的 false positive／false negative 邊界。 |
| **Low** | **Markdown 與列印版兩種報告形式可能重複。**G4 只要求「報告」，沒有要求兩種格式。 | 兩個輸出表面需同步維護欄位與措辭。 | 選一種作為 v1 正式報告；另一種只有在具體教學流程需要時再列入需求。 |
| **Low** | **兩套 CASP 工具可能重複大量題目與維護工作。** | 若其實是同一官方 checklist 的不同教學情境，雙份內容容易版本漂移。 | `[需查證]` 先確認 CASP 2024 是否確有兩份不同官方工具；若沒有，採一份正式 checklist，RCT／observational 只作不同 mock paper 或教學 profile。 |
| **Low** | **三引擎分離不是 over-engineering。**CASP、RoB 2、GRADE 的判讀語意確實不同。 | 強行合併才會造成更高重工。 | 保留 D4，但移除未有官方依據的 CASP 自動 overall 行為。 |

結論：r1 的平台與模組方向可以保留；應先修訂方法學來源鎖定、GRADE 合法規則、版本不可變性與 schema 契約，再開始引擎及匯出格式。最優先阻擋項是 A5 的 GRADE oracle、RoB 2 的正式 algorithm locator，以及 D5 從「實跑一次」提升為方法學簽核門檻。
